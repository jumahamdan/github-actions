# Candidate evidence and release notes

A release candidate records its product/version/build, original commit and source tree, library revision, toolchain, input/artifact checksums and typed check receipts. `evidence.create` requires clean tracked source and real nonempty artifacts. Each check declares `{path, kind, config}`; its configuration must also be a candidate input. The shared action stamps the receipt with its source and configuration identity. A bare `{status: passed}` cannot satisfy this contract. Security checks additionally require the current policy and fresh results when the candidate is verified.

Hashes establish content equality, not authorship. Retrieve retained candidates from an authenticated successful GitHub run with the expected repository, workflow, source, attempt and artifact identity. Do not accept a candidate merely because its JSON and hashes agree. Promotion verifies the entire merged source tree, expected library revision and toolchain. A changed relevant input or stale security scan requires fresh evidence. A merge commit with the same source tree does not require rebuilding the app.

Use the existing candidate on `staging` and `main`. A required gate refuses missing, cancelled, failed or unexpectedly skipped checks. A check may be inapplicable only when the caller explicitly declares that policy. Provider rebuilds, including Firebase Functions and source-based hosting, are recorded as rebuilds from the same source; they cannot claim byte-identical artifacts.

Release notes use explicit `public`, `testers` and `internal` audience allowlists. [The notes example](../examples/release-notes.json) keeps customer changes separate from operational details. PR-derived categories are drafts bounded by the previous tag and chosen candidate; duplicate and promotion PRs are omitted. Authored summaries and product-specific required fields remain reviewed product content. Store adapters enforce their own destination limits and review states.

GitHub publication requires an existing approved tag, expected current commit, expected library SHA and expected toolchain. It verifies notes match the candidate, creates/resumes a draft, checks every asset's bytes and complete remote inventory, and publishes only when explicitly configured. Conflicting or unexpected assets fail. An interrupted zero-byte upload can be removed only from a draft; published assets are never silently replaced. Save operation evidence and reconcile uncertain provider responses before retrying.

A published GitHub release does not establish TestFlight availability, completed store review or public app availability. Those are separate store operations. Product promotion authority remains with the product owner; this library neither merges promotion PRs nor changes branch policies.
