**Shared checks:** [Check settings](https://github.com/alivedoctor/alivedoctor/tree/develop/.ci/quality/) · [Reuse settings](https://github.com/alivedoctor/alivedoctor/tree/develop/.ci/reuse/) · [Shared-action wrapper](https://github.com/alivedoctor/alivedoctor/blob/develop/.github/actions/shared-quality/action.yml). Unchanged promotion checks can reuse a verified result; secret scans and admin page builds run fresh.

**Release route:** feature → develop → staging → main. You decide when to promote. The App Store uses the tested TestFlight build.

**Release notes:** write them once in `CHANGELOG.md`. The pinned shared module checks and formats them before promotion. The GitHub Release keeps all three sections; public and tester versions omit sections outside their audience. Approval, tags and publication stay in AliveDoctor's release command. TestFlight tester-note delivery is separate.

**Backend CD:** active. [AWS access was configured](https://github.com/alivedoctor/alivedoctor/issues/250#issuecomment-7071271305), and your [first approved promotion deployed production automatically](https://github.com/alivedoctor/alivedoctor/issues/250#issuecomment-7074665435) on 2026-11-21. CD deploys the approved backend version independently of the website and verifies it, without repeating the PR's AI tests. Manual deployment remains the fallback if a run fails.

**AWS login verified:** [Staging](https://github.com/alivedoctor/alivedoctor/actions/runs/44863081366) and [production](https://github.com/alivedoctor/alivedoctor/actions/runs/44863084406) passed without publishing website content.
