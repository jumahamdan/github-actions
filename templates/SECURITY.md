# Security policy

Before adopting this template, maintainers must publish the supported product versions and verify the private reporting route below. Do not publish it with placeholder contacts or an unmonitored channel.

## Supported versions

Maintain a table here identifying the exact product versions receiving security updates, including the supported mobile release and deployed server version. A version being available to download does not by itself mean it remains supported.

## Report a vulnerability

Use this repository's **Security → Advisories → Report a vulnerability** option when private vulnerability reporting is enabled. If that option is unavailable, use the product's published private security contact. Maintainers must provide and verify that contact before adopting this policy.

Include affected versions, expected and observed behavior, reproduction steps, impact, and a minimal synthetic example where possible. Keep credentials, patient/customer information, production database contents, and active exploit instructions out of public issues and pull requests. Never include a live secret in a report; name the affected credential and privately coordinate rotation.

Maintainers acknowledge reports through the chosen private channel, investigate, and agree a disclosure plan with the reporter. Product-specific response commitments and support periods belong in this policy only when the responsible owner has agreed to them.

## Changes and disclosure

Security fixes follow the repository's review and verification process. Authorized maintainers coordinate release timing, credential rotation, customer communication and any advisory. Automated scan results are evidence for review, not authorization to publish private findings or deploy a release.
